The full solution in five steps

Each stage has one job. Its output becomes the next stage's input.

01 · LEARN

Prepare trip data

Clean real TLC trips and split earlier dates for training from later dates for testing.

02 · ESTIMATE

Predict travel minutes

The selected model estimates travel between zones by hour. The NN predicts trip duration.

03 · ASSIGN

CSP picks vans

Assign each generated order to a van without breaking capacity or time-window rules.

04 · ORDER

A* plans stops

For each van, choose a feasible stop order using travel, waiting, and service time.

05 · RETRY

Repair conflicts

If a route fails, add a different-van rule for the conflicting orders and solve again.

MAE · mean absolute error

Average size of the prediction miss. This NN's MAE is 5.09 minutes.

RMSE · root mean squared error

Also an error in minutes, but large misses count more. It is often higher than MAE.

Baselines

Simple reference methods: historical average for a zone pair, or an estimate based on distance.

Important: the held-out test measures prediction accuracy on taxi trips. It does not measure courier lateness or prove that taxi durations equal van travel times.

Step 5 · Compare route-search methods

A*, UCS, and Greedy are run on the same final van assignments. Only the route-search method changes, so this compares how each method orders the same stops.

MethodResult Total route cost across vansRoute states expandedRoute states generated
No assignment was available for a route-search comparison.
A* · cost so far + estimate

Uses time already spent plus a lower-bound estimate of the remaining travel. It can find an optimal route when its search completes.

UCS · cost so far

Explores the route with the least cost so far. It can find an optimal route, usually by exploring more possibilities.

Greedy · estimate first

Chooses routes that look closest to finishing. It can be quick, but is not guaranteed to find the lowest-cost route.

How to read the numbers: lower route cost means fewer estimated minutes for travel, waiting, and service. “Expanded” counts route states the method examined; “generated” counts possible next states it added to its search. These counts cover all vans together for this one seeded demo, not the five-seed experiment.

Step 6 · Read the route schedule

After the CSP assigns orders, A* decides the order each van visits its stops. It uses the predicted travel minutes and checks whether each arrival fits the order window.

A route timeline is shown only when the scenario has a feasible assignment and route.

What is a route state?

A snapshot: current zone, orders already visited, and current time. One possible next stop creates a new state.

What do the search numbers mean?

Expanded = a route snapshot A* examined. Generated = a possible next snapshot added to its queue.

What is route cost?

Total estimated minutes for travel + waiting for windows + service at stops. A* searches for a low-cost feasible order.

Travel-time caveat

TLC taxi trip durations approximate travel between zones; they are not measured courier-van times.

Evaluation caveat

The model's MAE/RMSE evaluate held-out real taxi trips. They do not measure actual courier lateness or delivery performance.

Read the chart: the blue bar is the order's allowed time window; the dot is the estimated arrival. Green means the arrival fits the window; orange means it does not. The predicted arrivals and generated orders are a demo, not real delivery outcomes.
